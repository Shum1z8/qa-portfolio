# Тест-кейсы — Petstore API

## Позитивные сценарии

### TC-001: Создание питомца
Проверяю, что можно создать нового питомца через POST-запрос.

Шаги:
1. Отправить POST /pet с валидными данными (id, имя, статус).
2. Проверить ответ.

Ожидаемый результат: сервер возвращает 200, питомец создан.

### TC-002: Получение питомца по ID
Проверяю, что можно получить питомца по его ID.

Шаги:
1. Отправить GET /pet/676767.
2. Проверить ответ.

Ожидаемый результат: сервер возвращает 200, данные совпадают с созданными.

### TC-003: Обновление питомца
Проверяю, что можно изменить данные питомца.

Шаги:
1. Отправить PUT /pet с новыми данными (имя, статус).
2. Проверить ответ.

Ожидаемый результат: сервер возвращает 200, данные обновлены.

### TC-004: Удаление питомца
Проверяю, что можно удалить питомца по ID.

Шаги:
1. Отправить DELETE /pet/676767.
2. Проверить ответ.

Ожидаемый результат: сервер возвращает 200, питомец удалён.

## Негативные сценарии

### TC-005: Получение несуществующего питомца
Проверяю, как API реагирует на запрос несуществующего ID.

Шаги:
1. Отправить GET /pet/999999.
2. Проверить ответ.

Ожидаемый результат: сервер возвращает 404.

### TC-006: Создание питомца без тела запроса
Проверяю, что произойдёт, если отправить POST без данных.

Шаги:
1. Отправить POST /pet без body.
2. Проверить ответ.

Ожидаемый результат: сервер возвращает 400 или 405.

### TC-007: Обновление с битым JSON
Проверяю, как API реагирует на невалидный JSON.

Шаги:
1. Отправить PUT /pet с битым JSON.
2. Проверить ответ.

Ожидаемый результат: сервер возвращает 400.

### TC-008: Удаление несуществующего питомца
Проверяю, как API реагирует на удаление несуществующего ID.

Шаги:
1. Отправить DELETE /pet/999999.
2. Проверить ответ.

Ожидаемый результат: сервер возвращает 404 или 200 (зависит от API).
